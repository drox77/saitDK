# D&K — ДНК вашего бизнеса

Одностраничный сайт агентства: шесть секций, анимированная спираль ДНК, карусель проектов и форма заявки с отправкой в Telegram двум получателям.

Внешних зависимостей нет. Сайт разворачивается на Vercel или запускается как обычный сервер Node.js.

## Развёртывание на Vercel

1. Загрузите в репозиторий GitHub все файлы проекта, включая `vercel.json`, папки `api/` и `scripts/` и файлы с точкой в начале имени.
2. В Vercel: Add New → Project → выбрать репозиторий. Настройки сборки менять не нужно, они записаны в `vercel.json`.
3. В Settings → Environment Variables добавьте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_IDS`.
4. Нажмите Deploy. После изменения переменных нужен новый деплой (Deployments → Redeploy).

Как это устроено: `scripts/build.js` собирает статику в `dist/`, а форму обслуживают две функции — `api/csrf.js` и `api/lead.js`.

Особенность Vercel: лимит заявок по IP и защита от дублей хранятся в памяти экземпляра функции. Экземпляров может быть несколько, и они перезапускаются, поэтому эти защиты работают не строго: настойчивый бот может превысить лимит, а повтор после частичной доставки может продублировать сообщение одному из получателей. Чтобы сделать их строгими, нужно внешнее хранилище, например Upstash Redis.

## Локальный запуск

Нужен Node.js 20.12 или новее.

```bash
cp .env.example .env    # затем заполнить .env
npm start               # http://localhost:3000
npm test                # 34 теста, сеть не нужна
```

Тот же `npm start` подходит для хостингов с постоянным процессом (VPS, Render, Railway): там нужны ещё `NODE_ENV=production` и `TRUST_PROXY=1`.

## Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | Токен бота от @BotFather |
| `TELEGRAM_CHAT_IDS` | да | ID получателей через запятую |
| `SITE_URL` | когда появится свой домен | Адрес сайта без слэша на конце: canonical, Open Graph, `sitemap.xml`, `robots.txt`. На Vercel по умолчанию берётся основной адрес проекта |
| `CSRF_SECRET` | нет | Случайная строка от 32 символов. Если не задана, секрет выводится из токена бота |
| `NODE_ENV`, `TRUST_PROXY`, `PORT`, `HOST` | только вне Vercel | `production`, число прокси перед приложением, порт и адрес |
| `RATE_LIMIT_MAX`, `RATE_LIMIT_WINDOW_MIN` | нет | Лимит заявок с одного IP, по умолчанию 5 за 10 минут |

Без токена или ID получателей сайт открывается, но форма отвечает ошибкой 503 и не показывает успех. Чего не хватает, видно в логах по событию `config_warning`.

## Подключение Telegram

1. **Смените токен.** Токен, который был передан в чате, считается раскрытым. В @BotFather: `/revoke` → выбрать @zayavkibusinesbot → скопировать новый токен.
2. Запишите новый токен в переменную `TELEGRAM_BOT_TOKEN` в панели хостинга (локально — в `.env`). Больше нигде его хранить не нужно.
3. Запишите получателей: `TELEGRAM_CHAT_IDS=id1,id2`.
4. Каждый получатель открывает бота и нажимает **Start**. Пока человек этого не сделал, Telegram отвечает `403 Forbidden`, и заявка считается недоставленной.
5. Сделайте новый деплой и отправьте тестовую заявку с сайта. Сообщение должно прийти обоим.

Правила обращения с токеном:

- только в переменных окружения хостинга или в локальном `.env`; `.env` уже в `.gitignore`;
- не в коде, не в README, не в `.env.example`, не в переменных с префиксом `NEXT_PUBLIC_` / `VITE_`;
- при любой утечке — сразу `/revoke`.

Сервер не пишет токен в логи: при сетевой ошибке в лог попадает только её тип, а не адрес запроса.

## Как работает заявка

1. Форма проверяет поля в браузере теми же правилами, что и сервер (`public/js/lead-rules.js`).
2. Сервер проверяет лимит по IP, заголовок `Origin`, CSRF-токен, размер и формат тела, поле-ловушку и сами поля.
3. Каждому получателю уходит отдельный запрос `sendMessage`: таймаут 2,5 секунды, до трёх попыток при сетевой ошибке, 5xx или 429.
4. Пользователь видит «Заявка отправлена» только после `ok: true` от обоих получателей.
5. Если один получил сообщение, а второй нет, форма показывает ошибку. Повторная отправка тех же данных уходит только второму.
6. Одинаковые данные в течение 15 минут доставляются один раз.

Заявки не сохраняются на диск. Если Telegram недоступен дольше трёх попыток, заявка теряется, а пользователь видит ошибку и может отправить её снова.

## Что нужно сделать перед публикацией

- **Превью проектов.** В `public/img/projects/` лежат заглушки с названием проекта, а не скриншоты. Снимите первый экран каждого сайта в размере 1280×800, сохраните в WebP под теми же именами (`<проект>-1280.webp` и уменьшенную копию `<проект>-640.webp`) — код менять не нужно.
- **Политика конфиденциальности.** В `public/privacy.html` выделены места, куда нужно вписать оператора, контакт, срок хранения и дату. Текст стоит показать юристу.
- **Шрифты.** Manrope и Inter подключены с Google Fonts. Для скорости и приватности лучше положить файлы `woff2` в `public/fonts/`, описать их через `@font-face` в `styles.css`, убрать ссылки на Google из трёх HTML-файлов и домены Google из CSP в `src/app.js`.
- **Домен.** Когда подключите свой домен, задайте `SITE_URL` и сделайте новый деплой.

## Что где менять

- Цвета, шрифты, размеры, отступы, радиусы — переменные в начале `public/css/styles.css`.
- Цвет кнопок — `--btn-bg` и `--btn-fg` там же.
- Скорость спирали — атрибут `data-period` (секунды на полный оборот) у блока `data-helix` в `index.html`.
- Тексты, услуги, цены, проекты — `public/index.html`. Цены продублированы в блоке JSON-LD в `<head>`.

## Безопасность

- Content-Security-Policy без `unsafe-inline`: скрипты и стили только со своего домена, шрифты — с Google Fonts. На Vercel те же заголовки для статики заданы в `vercel.json`; при изменении CSP правьте оба места, тест проверит совпадение.
- `X-Frame-Options: DENY`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, HSTS в продакшене.
- CORS-заголовки не выставляются: API доступно только со своего домена.
- Пользовательский ввод не вставляется в HTML; в Telegram уходит обычный текст без разметки.
- Сообщения об ошибках для пользователя не содержат внутренних деталей.

Клиентский код виден любому посетителю — защита строится на серверной части. Лимиты и защита от дублей хранятся в памяти процесса и сбрасываются при перезапуске.
